# Hermetic contract batteries

These batteries drive the **built** package (`dist/`) as a user would: the `ur` CLI as a real
process, and the client and the `@ultrarouter/sdk/context` subpath as published modules. Each one
starts its own stubs on `127.0.0.1` (a stub gateway, a stub GitHub REST API, stub harness commands,
throwaway git repositories), so they need **no network, no credentials and no running gateway**.
Every battery exits non-zero on any failed check, and a battery whose `dist/` input is missing
fails with a "build first" message instead of passing vacuously.

The unit suite (`npm test`) proves the same rules at the function boundary; these batteries prove
them end to end through the shipped artifacts.

## Run them

```bash
npm run build      # the batteries resolve dist/
npm run contract   # runs contract-tests/run-all.mjs: every battery + the bench gate smoke
```

Run a single battery with `node contract-tests/<name>/run.mjs`, or a single suite of the two
multi-suite batteries with `node contract-tests/app-ci/test-app-binding.mjs` (and so on). `git`
must be on `PATH` for `app-ci` and `flywheel-ci` (the baseline revision runs in a `git worktree`
of a fixture repository).

## The batteries

| Battery        | Drives                                                       | Proves                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app-ci/`      | `ur app-ci` + `action.yml`                                   | Change detection binds each changed path to its workflow; an unmapped change is `Needs configuration` (never a pass). Evidence is content-addressed: any bound-input change, including a configuration change outside Git, marks a previously green check stale. Fork PRs never execute the harness; a normal run executes it with a scrubbed environment (no `GITHUB_TOKEN`, no API key). A raw-model pass with an application schema failure **blocks** (`Regression found`, Check Run `failure`, exit 2), and a `model_call_only` comparison can never claim application coverage. Debug excerpts are redacted and capped at three. The action's dispatch guard fails closed on an unknown or legacy `mode`.                                                                                                                       |
| `flywheel-ci/` | `ur flywheel-pr` + `action.yml`                              | With repository write granted, a branch is created and a **draft** PR opened, and no merge request is ever made. Without write (denied or unreadable), a downloadable patch is produced that `git apply --check` accepts, and the identical check runs. Without `--apply`, the diff and destination branch are shown and nothing is written. Both change shapes (`code_owned`, `gateway_owned`) are classified on the observed diff; out-of-surface changes are refused before any write. The candidate reference is recomputed from its provenance, a tampered body is refused, and only `screened` candidates travel. The rollout decision is read from the server, rendered blocker by blocker, never pressed, and fails closed to `authorization_unavailable`. A human decision is signed, and a replay is a visible `duplicate`. |
| `cli/`         | `ur outcomes`, `ur flywheel`, `ur import`, `ur context lint` | The exit-code contract per command: 0 on success, 2 on a partial rejection (with the rejected rows listed) or any read/API error, 1 on a usage error. Re-importing the same outcomes file is all duplicates.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `preflight/`   | `preflight()` + `useLearned()`                               | The two cache lifetimes (ETag-revalidated config part, 30-second live part); the grant is never cached (a cached 304 still yields a fresh `X-UR-Grant`); the learned module is placed after the leading system messages; `apply()` always injects on this non-proxied path; `record()` quotes the grant; a holdout arm passes messages through unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `reviewer/`    | `ur.reviewer.*`                                              | The signature on the wire verifies against an independent recomputation over the received bytes; a wrong key is refused by name; a replayed `event_id` is a `duplicate`; a `version_mismatch` dead letter survives locally and is repaired; an event carrying `learning_use` / `source` / `producer` is refused.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `flywheel/`    | artifacts, outcomes, imports, status                         | Every method sends the right method, path and body. The retry rule end to end: an outcome recorded and then answered with a 503 stays queued, and `flush()` replays it byte-identically so the server sees a `duplicate`, while a same-key different payload is a `conflict`. `ur.manifest` rides the chat body verbatim.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `context/`     | `@ultrarouter/sdk/context` (built)                           | The subpath exports the runtime and the client entry does not; `toMessages(fromMessages(m))` is byte-identical to `m` after a JSON round trip for every synthetic sample; the bundled `zod` works; the default-profile manifest matches the committed golden (`test/context/fixtures/ultrarouter/default.json`) byte for byte.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

`run-all.mjs` also runs `scripts/action-smoke.mjs`, which drives `ur bench run --gate` against a
stub gateway and asserts pass ⇒ 0, fail ⇒ 2, inconclusive ⇒ 2 (0 with `--allow-inconclusive`) and
API error ⇒ 2.

## Writing a new battery

Keep it hermetic: start stubs on `127.0.0.1:0`, never call a real provider or a hosted gateway,
and spawn the CLI **asynchronously** when the stub runs in the same process (a synchronous spawn
blocks the event loop and deadlocks the child's request). Resolve the built files from `dist/`,
fail with a "build first" message when they are missing, exit non-zero on any failed check, and
add the entrypoint to `run-all.mjs`.
